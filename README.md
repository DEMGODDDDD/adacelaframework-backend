## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.

## Demgod Aquatics storefront

- `/` is the login, registration, and guest entry page.
- `/shop` and `/customer` open the responsive customer/guest shopping experience.
- Run `php artisan migrate` to create or update the application tables, then `npm run build` to compile the frontend.
- The storefront loads active products and categories from `/api/products` and `/api/categories`. Customer cart, wishlist, order, and review actions use the authenticated API.

## Administrator access

- Set `ADMIN_USERNAME` (defaults to `demgod`), `ADMIN_EMAIL`, and a strong `ADMIN_PASSWORD` in the server environment. Never commit the password or put it in frontend code.
- Run `php artisan migrate`, then `php artisan db:seed --class=AdminUserSeeder` to create/update the admin account. The seeder stores a password hash; it fails explicitly if the email or password is not configured.
- The admin sign-in form accepts the configured username. Admin pages under `/admin` verify the bearer token and role against the API, and all management endpoints enforce the admin role on the server.
- Management supports dashboard metrics/activity, user roles and account activation, product CRUD and image upload, inventory thresholds and adjustments, order lifecycle updates, review moderation/replies, and sales/inventory exports.

## Separate frontend deployment

- Set `FRONTEND_URL` to the frontend's origin (or a comma-separated list of origins) so the API and uploaded images can be requested cross-origin.
- The standalone React frontend reads `VITE_API_BASE_URL`, which must point to this backend and end in `/api`. Admin and customer authentication use bearer tokens; do not enable credentialed cookies for the public frontend.
- Keep deployment secrets in the backend host's environment, never in the frontend build variables.
